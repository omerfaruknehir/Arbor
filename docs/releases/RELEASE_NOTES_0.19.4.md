# Arbor 0.19.4

## Provider-agnostic image generation

Arbor can now treat image-generation models as first-class models rather than chat models which happen to return text.

- OpenAI and OpenAI-compatible API providers route image-capable models through `POST /images/generations`.
- The bundled catalog includes GPT Image 1 and GPT Image 1 Mini.
- Discovered model IDs such as `gpt-image-*` and `dall-e-*` are marked automatically.
- Any OpenAI-compatible model can be marked **Image generation** in the model editor for compatible third-party endpoints.
- DALL·E-compatible models request base64 output, while GPT Image-compatible models use `output_format`, `quality`, `background`, and `size` controls.

## ChatGPT OAuth image tool

A ChatGPT OAuth model can expose the Responses `image_generation` tool. Arbor serializes that tool only when the account catalog or the model editor marks the model as image-capable, decodes completed `image_generation_call` results, and keeps large image payloads out of replay JSON.

Because the ChatGPT Codex backend is private and account-dependent, image generation is shown only when the backend/model advertises or accepts it. A backend rejection is surfaced as a provider error rather than silently falling back to another account or API.

## Generated-image lifecycle

- Generated bytes are validated and saved into Arbor's existing internal attachment store.
- Images appear inline on the assistant message and use the existing full-screen viewer, save, share, and attachment persistence behavior.
- Retry follows the original provider/model snapshot, including the image-generation capability.
- A generated image is valid assistant output even when no text accompanies it.
- Each image has a 64 MB safety limit and the API JSON response has a 96 MB limit.

## Scope and compatibility

This release supports text-to-image generation. Image editing or variation requests with an input image are rejected with a clear message instead of being sent to the wrong endpoint.

- Version code: 114
- Application ID: `app.arbor.chat.debug`
- Room schema migrates from 13 to 14 by adding `models.supportsImageGeneration` with a safe default and automatic marking of known image-model IDs.
- Existing chats, providers, OAuth accounts, settings, attachments, workspaces, signing compatibility, and blur implementation are preserved.
